# GutPacer

**介護者が日々の排便・服薬・体調を記録し、あとから確認するためのWebアプリです。**

[English](README.md) · [開発への参加](CONTRIBUTING.md)

スマートフォン向けの日本語画面から、日別の記録、修正、履歴表示、PDF出力ができます。「確認して排便がなかった」と「まだ記録していない」を区別します。診断や治療方針の提案は行いません。

## 現在の範囲

開発中です。基本のPIN APIは、設定済みの1世帯を対象とします。LINE認証APIと機械可読な観察データ出力は、別の限定公開向け経路として実装されています。ソースが存在することは、一般登録や複数世帯向けサービスの提供開始を意味しません。

| 機能 | 範囲 |
| --- | --- |
| 日々の記録 | 排便の量・状態、明示的な「なし」、服薬時間帯、体調、メモ |
| 履歴・修正 | 日付ごとの記録を更新・削除。更新前の全履歴を保管する仕組みではありません |
| 閲覧用画面 | 同じ画面内の表示モード。職員専用アカウントや独立した権限ではありません |
| PDF | ブラウザーで人が読む報告を生成 |
| LINE通知 | 記録の確認を促す通知。通知無効や施設設定のプロフィールは送信対象から外れます |
| JSON出力 | LINE APIの `care-event/v1` スナップショット。基本PIN APIには未接続 |

## アカウントなしで画面の試作を見る

GitとPython 3を使います。AWS認証情報やLINEログインは不要です。

```bash
git clone https://github.com/larai-w/GutPacer-ParkinSync-Module.git
cd GutPacer-ParkinSync-Module
python3 -m http.server 8000 --bind 127.0.0.1
```

**http://127.0.0.1:8000/prototypes/display-directions.html** を開きます。入力・履歴・閲覧・報告の場面と、4種類の表示案を切り替えられます。終了は `Ctrl+C` です。

既存の静的な画面試作で、サンプル表示のみです。保存やAPI通信は行いません。一部の文言は以前の設計を反映しているため、実際の意味は下記の記録ルールと現在の `frontend/index.html` を参照してください。

実際のアプリは **http://127.0.0.1:8000/frontend/** です。Git管理外の `frontend/config.js` と、互換性のある開発用APIが必要です。静的サーバーだけでは認証・保存・履歴取得は動きません。[英語READMEの設定例](README.md#local-preview)を参照してください。既存の設定を上書きしたり、本番の記録先に開発画面を接続したりしないでください。

## 構成

- `frontend/index.html`: ビルド不要の静的画面。ブラウザー用ライブラリーはCDNから読み込みます。
- `backend/index.mjs`: 基本のPIN API。DynamoDBの `gutpacer-logs-v2` に世帯単位・日付単位で記録します。
- `backend/index-mvp.mjs`: LINE認証API。検証したIDとプロフィールから世帯を決定し、観察データを出力します。
- `backend/notifier/index-mvp.mjs`: 現行通知処理のソース。プロフィールと世帯の記録を読み、LINEへ送信します。
- `backend/notifier/index.mjs`: 旧通知処理。同じLambdaを置き換え得る手動ワークフローがあるため、取り違えに注意してください。
- 静的配信はS3/CloudFront、APIはLambda、永続化はDynamoDBです。

環境変数名・各モジュールの境界は[英語READMEの構成説明](README.md#architecture)にまとめています。設定ファイルだけでAWSやLINEの環境が作成されるわけではありません。

## 記録の意味

| 入力 | 扱い |
| --- | --- |
| 排便の詳細を選択 | `observed` |
| 「排便なしを確認した」を明示 | `confirmed_none` |
| 排便について未選択 | `not_recorded`。「未確認・記録なし」と表示 |
| 服薬時間帯が未記録 | 「記録なし」。服薬しなかった証拠にはしません |
| その日の保存記録がない | 出力イベントなし。確認済みの「なし」とはしません |

過去の記録に明示的な `bowelConfirmedNone` がない場合も、未確認として扱います。この表示によって保存済みデータを書き換えることはありません。

JSON出力は現在の状態のスナップショットです。日単位の精度、仮名化ID、変換情報を持ちますが、訂正履歴の台帳ではありません。自由記述のメモを含み得るため、仮名化しても公開可能なデータとは限りません。[出力仕様](docs/CARE_EVENT_EXPORT.md)と[スキーマ](schema/README.md)を参照してください。

ParkinSyncへの本番自動取込、臨床FHIR連携、学習済みMLモデルや評価済みの臨床予測は実装していません。

## 開発用チェック

主要ワークフローに合わせたNode.js 24と、公開範囲チェック用のPython 3を使用します。

```bash
npm ci
npm test
```

スモークスクリプトとNodeのテストを実行します。DynamoDBを置き換えるモックや合成データを使う検査であり、本番のAWS・LINEの動作確認を代替するものではありません。[検査対象とCIへのリンク](README.md#engineering-checks)を参照してください。

公開ファイルをステージした後は、次のガードも実行します。

```bash
python3 scripts/check_public_repo.py --staged
```

## 運用上の制約

- PINはブラウザーの `localStorage` に保存され、世帯で共有します。利用者ごとの本人確認ではありません。
- 閲覧専用表示は画面上の制限です。サーバー側の職員権限を追加するものではありません。
- 通知は記録不足の確認用です。身体の状態や必要な処置を判定しません。
- 出力後のデータは、元の記録を削除しても自動的には削除されません。
- **READMEだけの変更でも、`main` へpushするとフロントエンドが自動デプロイされます。** 文書のブランチ公開と、本番へ影響するマージは分けて判断してください。
